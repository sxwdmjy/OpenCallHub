# openCallHub 端到端深度重构设计文档

日期：2026-05-19

## 0. 背景与目标

openCallHub 当前基于 Java 17、Spring Boot、Vue 3、FreeSWITCH、Kamailio、Redis、MySQL 等技术栈，已具备呼叫、IVR、外呼、电话条、系统管理等基础能力。本次重构面向单企业私有化部署，不做最小闭环，而是设计完整联络中心平台，并采用深度重构、分阶段交付。

关键决策：
- 产品定位：单企业私有化全联络中心平台。
- 功能范围：呼入、人工外呼、AI 外呼、IVR、ACD、坐席、客户、工单、知识库、质检、报表、资源、权限、运维。
- 权限范围：完整权限体系但不做 SaaS 多租户，支持部门、技能组、客户池、任务范围隔离。
- AI：ASR/TTS 可配置，支持 RAGFlow、Dify、LangFlow 插件。
- 前端：专业 SaaS 风格控制台 + 沉浸式坐席工作台。
- 后端：模块化单体 + 事件驱动 + 未来可拆微服务边界。
- MQ：第一版 RabbitMQ，预留 Kafka 抽象扩展点。
- 部署：生产级 Docker Compose + 可观测性。
- 测试：生产级质量体系。

### 1.1 一级产品域

1. 首页与实时运营总览
2. 坐席工作台
3. 呼入中心
4. 外呼中心
5. AI 联络中心
6. IVR / 机器人流程设计器
7. ACD 排队与分配中心
8. 客户中心
9. 工单与服务记录中心
10. 知识库与话术中心
11. 资源管理中心

13. 质检中心
14. 报表与数据分析中心
15. 通知与消息中心
16. 系统与权限中心
17. 数据治理与合规中心
18. 运维、部署与可观测性中心

### 1.2 核心闭环

- 呼入：号码接入 → Kamailio → FreeSWITCH → ESL → IVR → ACD → 坐席 → 后处理 → 质检 → 报表。
- 人工外呼：客户导入 → 名单清洗 → 预览式任务 → 坐席领取 → 拨号 → 跟进 / 工单 → 报表。
- 预测外呼：任务 → 号码池与线路校验 → 预测拨号 → 坐席分配 → 风险调速 → 统计。
- 机器人外呼：任务 → AI 机器人 → ASR/TTS/Workflow → 意图与标签 → 转人工 / 跟进 → AI 质检。
- 治理：资源 → 权限 → 数据范围 → 审计 → 脱敏 → 导出控制 → 监控告警。

### 1.3 角色路径

系统管理员、运营主管、坐席、外呼主管、质检员、AI 机器人管理员、运维人员、安全/合规人员均有独立工作路径。

### 1.4 运营指标

呼入接通率、平均排队时长、放弃率、坐席利用率、外呼接通率、预测外呼放弃率、机器人转人工率、客户转化率、工单 SLA 达成率、质检合格率、AI 调用成本。

### 1.5 多角色评审

- 架构师：产品域完整，但必须用模块边界、状态机、事件一致性控制复杂度。
- 产品专家：业务闭环完整，需用模板和向导降低配置复杂度。
- 前端专家：18 个产品域必须分组导航，不可平铺。
- 后端专家：产品域应映射到领域模块，禁止 Controller 直接编排复杂业务。
- 通信专家：呼入、外呼、IVR、ACD、机器人链路必须贯穿 callId、uuid、legId。
- AI 语音专家：ASR、TTS、打断、静音、转人工、上下文必须纳入第一版。
- 运维专家：产品指标必须映射容量和告警。
- 安全专家：单企业内也必须做部门、技能组、客户池、任务、录音访问隔离。

## 3. 后端架构与模块边界

### 3.1 架构形态

采用模块化单体 + 事件驱动 + 未来可拆微服务边界。分为接口层、应用服务层、领域能力层、基础设施层。

### 3.2 模块

`och-api`、`och-system`、`och-resource`、`och-call`、`och-esl`、`och-ivr`、`och-acd`、`och-call-task`、`och-ai`、`och-customer`、`och-ticket`、`och-knowledge`、`och-quality`、`och-report`、`och-notice`、`och-batch`、`och-compliance`、`och-file`、`och-websocket`。

### 3.3 通信边界

Kamailio 负责 SIP 注册、路由、入口防护、负载预留；FreeSWITCH 负责媒体控制、拨号、桥接、录音、DTMF、保持、转接；RTPengine 作为复杂 NAT 和媒体代理预留；ESL 是 Java 后端控制 FreeSWITCH 的命令和事件通道。

### 3.4 事件一致性

RabbitMQ 用于业务事件和异步任务。业务主流程先本地事务落库，再通过 outbox 或可靠事件发布投递 MQ。事件必须有 `eventId`，消费端按幂等键去重，失败进入重试队列，超过阈值进入死信队列。

### 3.5 状态机

必须显式建模：通话状态机、坐席状态机、IVR 执行状态机、ACD 排队状态机、外呼任务状态机、AI 机器人会话状态机、批处理任务状态机、工单状态机。

### 3.6 多角色评审

- 架构师：`och-esl`、`och-call`、`och-ivr`、`och-acd` 职责必须隔离。
- 产品专家：模块拆分不能导致用户体验割裂。
- 前端专家：统一响应、分页、错误、权限、审计和依赖检查契约。
- 后端专家：事务边界、幂等键、并发锁必须明确。
- 通信专家：通信层不承载外呼、ACD、IVR 业务策略。
- AI 语音专家：AI 插件抽象 ASR/TTS/LLM/Workflow。
- 运维专家：模块级健康检查和指标标签必需。
- 安全专家：跨模块调用必须传递用户、数据范围和 traceId。

## 5. 核心业务流程与事件流

### 5.1 呼入客服

用户拨号 → Kamailio → FreeSWITCH → ESL → `och-call` 创建会话 → 呼入路由 → IVR → ACD → 坐席弹屏 → 接听 → 后处理 → 记录、录音、服务记录 → 质检与报表。

### 5.2 IVR

支持菜单节点、日程判断节点、转语音信箱节点。菜单节点支持 DTMF、超时、错误输入、重试和默认分支。日程判断支持工作时间、节假日、特殊日期、技能组服务时段。语音信箱支持留言录音、处理状态、转工单和回拨。

### 5.3 ACD

呼叫进入技能组 → 校验队列容量和服务时间 → 等待提示 → 监听坐席状态 → 按空闲优先、轮询、最少接听、技能优先、权重、最近未接策略分配 → 超时重派 / 溢出 / 语音信箱 → 更新 SLA。

### 5.4 外呼三模式

预览式：坐席先看客户再手动拨号。预测式：系统根据坐席空闲、接通率、平均通话时长提前拨号，必须控制放弃率和并发。机器人外呼：接通后由 AI 机器人交互，支持 ASR/TTS/Workflow、意图、标签、转人工、AI 质检。

### 5.5 AI 实时语音链路

FreeSWITCH 接通 → 音频进入 ASR → 文本进入机器人会话 → 内置机器人或 Dify/RAGFlow/LangFlow 生成回复 → TTS 合成 → FreeSWITCH 播放 → 记录轮次、变量、意图、上下文、延迟和插件日志。预留 partial result、barge-in、TTS 中断、静音检测、无响应重试、上下文窗口和转人工兜底。

### 5.6 失败恢复与追踪

必须处理 ESL 断连、FreeSWITCH 不可用、Kamailio 路由失败、分机注册失败、事件重复/乱序/丢失、桥接失败、录音失败、DTMF 失败、AI 插件超时、任务重启恢复。每通电话贯穿 `traceId`、`callId`、`uuid`、`legId`、`agentId`、`taskId`、`ivrExecutionId`、`queueSessionId`。

### 5.7 多角色评审

- 架构师：主链路完整，但必须用状态机约束。
- 产品专家：覆盖真实联络中心场景。
- 前端专家：流程追踪、实时监控、异常提示必须可见。
- 后端专家：重复、乱序、任务恢复和重复拨打要靠幂等与锁。
- 通信专家：ESL 层保留原始事件。
- AI 语音专家：低延迟、打断、转人工是体验关键。
- 运维专家：失败恢复要转为监控和告警。
- 安全专家：录音、ASR 文本、摘要、号码需权限和审计控制。

## 6. 接口体系与契约

### 6.1 API 类型

REST + WebSocket + 异步任务。REST 路径包含 `/api/system/**`、`/api/resource/**`、`/api/call/**`、`/api/ivr/**`、`/api/acd/**`、`/api/outbound/**`、`/api/ai/**`、`/api/customer/**`、`/api/ticket/**`、`/api/knowledge/**`、`/api/quality/**`、`/api/report/**`、`/api/notice/**`、`/api/batch/**`、`/api/compliance/**`、`/api/ops/**`。WebSocket 路径为 `/ws/agent`、`/ws/monitor`、`/ws/notice`、`/ws/task`。

### 6.2 关键契约

统一响应包含 `code`、`message`、`data`、`traceId`。关键契约包括坐席电话控制、IVR 图数据、ACD 监控、外呼三模式、AI 插件、资源依赖检查、批处理进度、WebSocket 消息。

### 6.3 幂等与并发

幂等键：通话事件 `callId + eventType + eventTime`，外呼拨打 `taskId + customerId + attemptNo`，AI 插件调用 `sessionId + turnNo + pluginType`，批处理 `jobId + itemId`，通知 `bizType + bizId + templateId`。

并发控制：预测外呼并发、客户领取锁、号码池占用锁、分机绑定唯一性、IVR 发布锁、批处理并发、机器人并发、线路并发。

### 6.4 多角色评审

- 架构师：REST、WebSocket、异步任务分层清晰。
- 产品专家：覆盖关键角色路径。
- 前端专家：统一响应和 WebSocket 格式利于封装。
- 后端专家：幂等和并发需接口层与应用层共同保障。
- 通信专家：电话控制 API 返回受理结果，最终状态以 ESL 事件为准。
- AI 语音专家：AI 接口需返回延迟、失败原因和供应商响应摘要。
- 运维专家：接口需携带 traceId。
- 安全专家：WebSocket 必须鉴权并按数据范围推送。

## 7. 部署、可观测性与运维

### 7.1 部署拓扑

Docker Compose 生产级私有化部署。应用：api、web、nginx。基础：MySQL、Redis、RabbitMQ、MinIO 可选。通信：FreeSWITCH、Kamailio、RTPengine 预留。可观测：Prometheus、Grafana、Loki/Promtail、Alertmanager 可选。

### 7.2 容量与健康

容量维度：坐席数、并发通话数、外呼并发数、机器人并发数、日通话量、日外呼量、录音存储增长、RabbitMQ 堆积、MySQL 增长、Redis 会话容量、WebSocket 连接数。

健康检查：MySQL、Redis、RabbitMQ、ESL、文件存储、AI 插件、FreeSWITCH 进程、通道数、注册分机、Kamailio SIP 监听、坐席在线、队列等待、任务积压。

### 7.3 告警、灰度、备份

告警分级：P0 呼叫/数据库/FreeSWITCH 不可用；P1 外呼中断、ESL 断连、队列严重堆积、录音不可写；P2 AI 失败率高、报表积压、RabbitMQ 延迟；P3 磁盘、慢 SQL、普通任务失败。

回滚：后端、前端、数据库迁移、IVR 流程、机器人流程、配置、AI 插件配置。备份：MySQL、录音、语音素材、导入导出文件、配置文件和恢复演练。

### 7.4 多角色评审

- 架构师：Docker Compose 符合私有化部署目标。
- 产品专家：运维能力是私有化交付的一部分。
- 前端专家：运维页需提供健康摘要和排障入口。
- 后端专家：健康检查需检查依赖与业务能力。
- 通信专家：FreeSWITCH、Kamailio、ESL、注册分机、通道数必须监控。
- AI 语音专家：AI 延迟、失败率、成本需监控。
- 运维专家：容量、备份、告警、回滚是生产必需项。
- 安全专家：配置、证书、密钥不能暴露在日志和前端。

## 9. 分阶段实施路线

1. 基础工程与架构底座：启动、登录、权限框架、OpenAPI、traceId、RabbitMQ、Redis、迁移。
2. 系统权限与资源管理：角色菜单、号码、线路、分机、素材、AI 插件、依赖检查、审计。
3. 呼叫核心、IVR、ACD：呼入、菜单、日程、语音信箱、ACD 分配、轨迹。
4. 坐席工作台与呼入闭环：上线、弹屏、接听、保持、转接、挂断、后处理、录音、服务记录。
5. 外呼中心三模式：预览、预测、机器人外呼，DNC、黑名单、时间窗、任务进度。
6. AI 联络中心：ASR/TTS、Dify/RAGFlow/LangFlow、机器人会话、摘要、标签、成本。
7. 客户、工单、知识库、质检：导入、分配、跟进、工单、知识、人工质检、AI 复核。
8. 报表、通知、合规、批处理：日报、通知、导入导出、脱敏、录音权限、导出审计。
9. 部署、监控、性能、安全验收：Compose、SIP 注册、核心链路、监控、日志、备份、故障演练。

### 9.1 多角色评审

- 架构师：先底座、再核心链路、再外呼 AI、最后运营治理，顺序合理。
- 产品专家：每阶段都有可演示闭环。
- 前端专家：先设计系统和页面模式，再逐域实现。
- 后端专家：阶段一必须建立异常、响应、权限、事件、迁移、测试框架。
- 通信专家：通信核心应尽早打通。
- AI 语音专家：AI 放在呼叫、外呼、资源和插件底座之后合理。
- 运维专家：部署和监控从阶段一开始，阶段九生产强化。
- 安全专家：权限、审计、数据范围从阶段一、二开始。
